🥊 Category 1: Hardcore Technical & Architecture Cross-Questions
Q1 "Why use RAG and Vector Embeddings? Wouldn't simple SQL filters (Age, State, Income) be 100x faster and cheaper?"
Judge's Trap: They suspect you used an LLM/RAG just as an unneeded hackathon buzzword.
Winning Counter-Punch: "SQL filters only work when the citizen already knows bureaucratic terms (e.g. searching for 'Kisan Credit Card' under 'Subsidized Agricultural Credit'). But in rural Bharat, citizens speak colloquially: 'Mera fasal barish se kharab ho gaya, mujhe paisa chahiye'.
SQL cannot map 'fasal kharab' to PM Fasal Bima Yojana. We built a Hybrid RAG Pipeline: Vector embeddings (text-embedding-004) discover semantic intent from colloquial Hindi/Hinglish, while deterministic pre/post-filters enforce hard constraints (income ceiling, land size, caste). Zero hallucination + 100% discovery."
Q2 "Indian names are notoriously inconsistent. How does your OCR handle 'Smt. Anita Devi' vs 'Anita Kumari' or 'Sharma Ramesh'?"
Judge's Trap: They want to see if your OCR is a toy name.includes() or an ungrounded LLM prompt.
Winning Counter-Punch: "We built a deterministic Indian Name Reconciliation Engine (backend/routes/documents.js):
1. Honorific Normalizer: Automatically strips 15+ Indian titles (Shri, Smt, Kumari, Km, Late, Babu).
2. Token-Sort Jaccard Similarity: Accurately resolves inverted surname ordering ('Sharma Ramesh' ⟷ 'Ramesh Sharma' at 96% match).
3. Jaro-Winkler + Levenshtein Composite: Handles regional phonetic transliterations (Laxmi/Lakshmi).
Scores ≥80% auto-pass; 55–79% triggers a visual PARTIAL_MATCH for operator one-click sign-off. Regex never blocks a genuine citizen."
Q3 "What happens if the LLM hallucinates an eligibility rule or benefit amount during the conversation?"
Judge's Trap: They want to verify if your AI creates legal/operational liabilities.
Winning Counter-Punch: "We enforce Strict Context Grounding with structured JSON schema constraints:
• The LLM runs at temperature: 0.1 and is mandated to cite only from retrieved database context.
• Every AI answer returns citedSchemeIds. The UI renders official financial payout tables, helpline numbers, and portal URLs directly from our verified MongoDB database, not unconstrained LLM memory.
• For live web updates, /api/ai/live-search queries Tavily strictly restricted to official .gov.in and myscheme.gov.in domains."
Q4 "How does voice search work for rural dialects when browser Web Speech API fails on non-standard accents?"
Judge's Trap: Standard browser WebSpeech fails on noisy rural backgrounds and local phrasing.
Winning Counter-Punch: "We engineered a Dual-Engine Multimodal Voice Pipeline (backend/routes/audio.js):
• Primary: Ultra-low-latency Web Speech API for clean standard inputs.
• Secondary Fallback: Captures raw audio via MediaRecorder and streams WebM/WAV buffers directly to Gemini Multimodal Audio, prompted specifically for Devanagari Hindi and Hinglish verbatim transcription. It correctly captures rustic accents (Malwi, Bundelkhandi, Bhojpuri) that Google Web Speech drops."
🛡️ Category 2: Privacy, Security & Legal DPDP Compliance
Q5 "Are you storing citizen Aadhaar cards or PAN details? Isn't that illegal under the DPDP Act and Aadhaar Act?"
Judge's Trap: Storing raw citizen Aadhaar numbers or biometrics without a CIDR license violates Indian law.
Winning Counter-Punch: "NagarikSaathi enforces an architectural Zero-Storage & Data-Minimization Principle:
1. zeroStorageComplianceMiddleware intercepts all incoming API payloads. Any unmasked 12-digit number or biometric array is rejected immediately at the gateway.
2. Vision OCR immediately scrubs raw sequences to XXXX-XXXX-1234 in memory before client return or DB persistence.
3. Citizen chat sessions have a 24-hour TTL expiration in MongoDB. We never store physical biometric templates or raw government identity cards."
Q6 "What prevents someone from spamming WhatsApp OTPs or submitting fake applications?"
Judge's Trap: They want to test rate limits and application abuse resistance.
Winning Counter-Punch: "Three security layers protect the system:
• Rate Limiting: Express rate limiters restrict chat and auth calls to 20 req/min per IP.
• MongoDB TTL-Indexed OtpSessions: OTPs self-destruct in 300 seconds (expires: 300) and lock out after 5 invalid attempts.
• Mandatory Verification Barrier: The /submit-application route strictly blocks execution without a cryptographic verificationToken issued upon verified WhatsApp OTP."
